# Implementation Plan: Sonos Phase 2 — Service Discovery, Browse & Speaker Details

**Branch**: `029-sonos-phase2` | **Date**: 2025-05-11 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/029-sonos-phase2/spec.md`

## Summary

Three related enhancements to the Sonos widget: (1) enhanced service detection with multi-account Spotify support via `sn=` parsing and admin-assignable friendly labels, (2) extended speaker discovery to surface device details (model, software version, serial, hardware version) and stereo pair status, and (3) a browse panel redesign replacing 4 hardcoded tabs with a dynamic service selector dropdown. No new npm packages or database migrations required — leverages existing `node-sonos` library methods and `integration_configs` table for label storage.

## Technical Context

**Language/Version**: TypeScript 5.5+ / Node.js ≥ 20
**Primary Dependencies**: Fastify (backend), Drizzle ORM + better-sqlite3 (DB), React 18 + Vite + Tailwind + shadcn/ui (frontend), TanStack Query (data fetching), node-sonos v1.x (Sonos UPnP), Zod (validation)
**Storage**: SQLite via Drizzle ORM — existing `integration_configs` table (provider, key, value, updatedAt)
**Testing**: Vitest (unit + integration), Playwright (E2E)
**Target Platform**: Docker container on Synology NAS (host networking, LAN-only)
**Project Type**: Web application (pnpm monorepo: `backend/` + `frontend/`)
**Performance Goals**: Speaker discovery < 5s (already within DISCOVERY_TIMEOUT_MS = 5000ms); metadata polling unchanged at 5s intervals
**Constraints**: LAN-only, no internet dependency for core features; touch-friendly mobile-first UI; no new database migrations
**Scale/Scope**: Single household, typically 2–15 Sonos speakers, 1–5 music service accounts
