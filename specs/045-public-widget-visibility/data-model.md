# Phase 1 Data Model — Public Widget Visibility

**Feature**: `045-public-widget-visibility` | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

This feature adds two persisted fields to widget instances and one disposable
in-memory cache. Migrations `0027_*` and `0028_*` are generated by Drizzle after
editing the schema; they must not be hand-written.

## Persisted entity changes

### `app_widget_instances`

Defined in `backend/src/db/schema/index.ts`.

| Field | Storage | Nullability/default | Purpose |
| --- | --- | --- | --- |
| `publicVisibility` → `public_visibility` | text enum: `hidden` \| `read-only` \| `visible` | `NOT NULL DEFAULT 'hidden'` | Administrator-selected anonymous exposure mode. |
| `publicSourceUserId` → `public_source_user_id` | text FK → `users.id` | nullable, `ON DELETE SET NULL` | Internal principal used only when a widget's integration data is scoped to a user account, currently Sonos cloud. |

`public_visibility` is a column rather than part of `config_json` because it is
an authorization input used by bootstrap filtering and every public data
request. It must be queryable without parsing type-specific JSON.

`public_source_user_id` is never returned by public APIs. It avoids guessing an
account for anonymous Sonos cloud reads. It is intentionally general enough for
future account-scoped integrations without introducing per-provider columns.

No index is required initially. Resolution starts from one selected dashboard,
then its placeholders and widgets; it does not scan widgets by visibility
globally.

### Type changes

Backend and frontend dashboard types gain:

```ts
type PublicVisibility = 'hidden' | 'read-only' | 'visible';

interface WidgetView {
  // existing fields
  publicVisibility: PublicVisibility;
}
```

`publicSourceUserId` remains service-internal and is not part of `WidgetView`.

The layout-save and widget-update inputs accept `publicVisibility`. The route
passes `request.user.id` separately as the actor; clients cannot submit or
choose `publicSourceUserId`.

## Visibility semantics

There are three stored modes:

| Mode | Anonymous integration data | Anonymous controls | Signed-in behavior |
| --- | --- | --- | --- |
| `hidden` | Denied | Denied | Unchanged |
| `read-only` | Allowed for supported types | Denied | Unchanged |
| `visible` | Allowed for supported types | Denied | Unchanged |

`read-only` and `visible` are deliberately identical in this feature.
Constitution §I permits only GET-only public resources, so neither mode grants
anonymous state changes.

Effective bootstrap behavior also depends on the widget type:

| Classification | Types | Effective public behavior |
| --- | --- | --- |
| Intrinsically public | `clock`, `weather`, `calendar`, `links_list`, `single_link`, `markdown`, `iframe`, `photo_frame` | Retained in public bootstrap because they already render from public bootstrap data or an existing public read path. |
| Explicit exposure required | `pihole`, `unifi`, `sonos_music`, `stocks`, `app_shortcuts` | Retained only when mode is `read-only` or `visible`; data served through the new public snapshot route. |
| Never public | `docker`, `spotify`, `todo`, `system_status`, unknown/future types | Removed from public bootstrap regardless of stored mode; no public loader exists. |

The allowlists are backend-owned constants. Unknown future widget types default
to never public.

## Public source principal

Public requests have no user identity, but Sonos cloud tokens are stored per
user. Guessing the first OAuth account would be nondeterministic and could
expose the wrong household.

**Decision** — when an administrator changes a supported integration widget
from `hidden` to `read-only` or `visible`, the server stores that administrator's
user id in `public_source_user_id`.

Rules:

1. The actor is supplied by authenticated server context, never request JSON.
2. Changing a widget to `hidden` clears `public_source_user_id`.
3. Changing between `read-only` and `visible` keeps the existing source
   principal unless it is null; a null value is filled with the current actor.
4. New widgets default to `hidden` + null.
5. Dashboard duplication/import creates new widgets as `hidden` + null,
   regardless of source values in the original/export.
6. Deleting the source user sets the field null. The widget then becomes
   unavailable publicly until an admin saves an exposed mode again.
7. Local Sonos mode does not require the principal, but retaining the binding
   allows a later switch to cloud mode without guessing.
8. Pi-hole, UniFi, stocks and app shortcuts do not consume the principal.

Visibility-change structured logs contain actor id, widget id, widget type, old
mode and new mode. They do not contain OAuth account ids, credentials, endpoint
URLs or tokens.

## Public widget resolution

The authorization service accepts:

```ts
resolvePublicWidget(deviceContext, widgetId)
```

Resolution is structural:

```text
request device context
  → selected unauthenticated dashboard
  → its placeholders
  → their widget instances
  → exact widget id
  → supported type + exposed mode
```

It returns a service-internal `ResolvedPublicWidget`:

| Field | Type | Notes |
| --- | --- | --- |
| `id` | string | Server-resolved widget id |
| `type` | supported public integration type | Never unknown |
| `publicVisibility` | `read-only` \| `visible` | `hidden` never resolves |
| `config` | parsed type-specific config | Internal input to projection only |
| `publicSourceUserId` | string \| null | Internal; required by Sonos cloud loader |

Missing widget, hidden widget, unsupported type, widget on another dashboard,
and widget on no selected public dashboard all produce the same public 404.

## Public snapshot value objects

### `PublicWidgetSnapshot`

```ts
interface PublicWidgetSnapshot<T> {
  widgetId: string;
  type: PublicWidgetType;
  data: T;
  refreshedAt: string;
}
```

The route does not return the stored visibility mode or source principal. The
public frontend is always read-only.

### Cache entry

```ts
interface PublicSnapshotCacheEntry<T> {
  value?: PublicWidgetSnapshot<T>;
  freshUntil: number;
  staleUntil: number;
  retryAfter: number;
  refresh?: Promise<PublicWidgetSnapshot<T>>;
}
```

The cache key is `<widget-type>:<widget-id>:snapshot`. Only the final projected
public snapshot is cached.

Policies and stale windows are defined in
[research.md R5](./research.md#r5-cache-keys-ttls-and-invalidation).

## Payload shapes

All payloads are allowlists. Internal configuration rows and raw provider
responses are never spread into them.

### Pi-hole

One snapshot combines the existing stats and system-health display data:

```ts
{
  stats: {
    totalQueries: number;
    blockedQueries: number;
    percentBlocked: number;
    domainsOnBlocklist: number;
    uniqueClients: number;
    blocking: 'enabled' | 'disabled';
    timer: number | null;
  };
  system: {
    cpu: number | null;
    memory: number | null;
    load: [number, number, number] | null;
    temp: number | null;
    uptime: number | null;
  };
}
```

### UniFi

The normal display-safe stats shape already returned by
`fetchUnifiStats()`: clients, gateway, devices, WAN, Wi-Fi, IPS and health.
Configuration, base URL, credentials and debug/raw responses are excluded.

### Sonos

One read-only now-playing snapshot:

```ts
{
  groups: Array<{
    id: string;
    name: string;
    coordinatorId: string;
    playbackState: string;
    playerIds: string[];
  }>;
  players: Array<{ id: string; name: string; capabilities?: string[] }>;
  activeGroupId: string | null;
  playback: SonosPlaybackState | null;
  metadata: SonosMetadata | null;
  volume: SonosVolumeState | null;
}
```

The loader prefers playing or buffering groups, then paused groups, then stable idle
groups. `defaultGroupId` breaks ties within the best available playback state.
No favorites, queue, library, diagnostics, account email, OAuth status, service
labels or control endpoints are public.

### Stocks

```ts
{
  quotes: StockQuote[];
  fxRates: Record<string, number>;
  displayCurrency: string;
  markets: Record<string, { open: boolean; state: string }>;
}
```

Search and candle-history APIs remain authenticated; the public widget receives
only the data used in its default dashboard display.

### App shortcuts

```ts
{
  shortcuts: Array<{
    id: string;
    groupId: string | null;
    name: string;
    url: string;
    iconKey: string | null;
    iconUrl: string | null;
    orderIndex: number;
  }>;
}
```

Creation timestamps, update timestamps, ping configuration and management
metadata are excluded.

## Lifecycle and invalidation

Invalidate a widget snapshot after:

- visibility or widget configuration changes;
- widget deletion;
- public-dashboard designation changes;
- app-shortcut mutation/reorder for that widget;
- integration configuration or connection changes affecting that widget.

Authorization runs before cache access, so invalidation is not the permission
boundary.

The cache is process-local and disposable. Startup begins empty; shutdown needs
no persistence.

## Migration and compatibility

Generated migrations:

1. `0027_*` adds `public_visibility TEXT NOT NULL DEFAULT 'hidden'` and nullable
   `public_source_user_id`;
2. `0028_*` performs Drizzle's generated SQLite table recreation to apply the
   visibility check constraint and `ON DELETE SET NULL` foreign-key action;
3. every existing widget remains hidden by default;
4. signed-in dashboard behavior is otherwise unchanged.

The split is intentional. SQLite cannot add the required foreign-key action to
an existing column, while a one-step Drizzle recreation would try to copy the
new columns before they exist on upgraded databases.

Backup/export behavior:

- Full database backups naturally include both columns after schema migration.
- Dashboard export/import and duplicate operations deliberately do **not**
  preserve public exposure. Imported/duplicated widgets are `hidden` + null.

Rollback removes the two new columns only by restoring a pre-feature database
backup; no runtime downgrade migration is provided.
